# PaperReader v2.1.2

> 📖 **下载前请先阅读[用户说明书](../../user_instruction.md)**，了解安装、首次配置与日常使用。本页为中文发布说明，英文原文见 [v2.1.2.md](../../releases/v2.1.2.md)。

PaperReader v2.1.2 修复了源码工程声明特定 TeX 引擎（而非 XeLaTeX）时的 LaTeX 编译兼容性。

## 修复内容

- LaTeX 工程构建不再无条件强制使用 XeLaTeX。
- arXiv 源码包可通过 `00README.json` → `process.compiler` 声明编译器；PaperReader 现在遵循受支持的声明。
- TeX 源码也可通过惯例的 `% !TeX program = ...` 魔法注释声明编译器。
- TeX 魔法注释只读取源文件头部的一小段，不再加载整个 `.tex` 文件，避免大文件带来不必要的 I/O 与内存开销。
- 支持的编译器声明为 `pdflatex`、`xelatex`、`lualatex` 与 `latex`，映射到对应的 `latexmk` 引擎模式。
- 没有受支持声明的工程保持既有行为，默认仍用 XeLaTeX 编译。
- 编译器元数据通过显式白名单处理，不会直接插入命令行。
- 既有的 strict 编译 + `latexmk -f` 降级流程不变。

## 兼容性

这是向后兼容的补丁版本，无需数据库或数据迁移。未声明编译器的既有工程与 v2.1.1 完全一致，继续使用 XeLaTeX。宿主机仍需安装 TeX Live、`latexmk` 与所选 TeX 引擎。

该回归问题使用 arXiv 源码包 `2605.18309` 复现：其 `00README.json` 声明 `pdflatex`，而 v2.1.1 强制 XeLaTeX 并在 `\DeclareUnicodeCharacter` 处失败。使用 v2.1.2 的选择器后，工程按声明经 `latexmk -pdf` 分发编译。

## 验证

发布门禁在 Linux、macOS 与 Windows 上运行后端测试套件与 Python 编译检查，然后构建 Windows 可移植包与 macOS 应用并做冒烟测试。回归测试覆盖 arXiv `00README.json` 编译器选择、TeX 魔法注释选择、无声明时的 XeLaTeX 默认值、不受支持声明的安全回退，以及 API、`package.json` 与 package-lock 版本元数据的一致性。
