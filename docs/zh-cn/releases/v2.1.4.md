# PaperReader v2.1.4

> 📖 **下载前请先阅读[用户说明书](../../user_instruction.md)**，了解安装、首次配置与日常使用。本页为中文发布说明，英文原文见 [v2.1.4.md](../../releases/v2.1.4.md)。

PaperReader v2.1.4 让 Windows 应用可以稳定启动，修复了译文中中文渲染的问题，并将 Windows 列为官方支持平台。

## 修复内容

- **Windows 窗口启动。** 更早的 v2.1.x Windows 包可能在任何窗口出现前就失败：未固定的构建依赖 `pythonnet` 解析到 3.1.0，其 `Python.Runtime.dll` 无法在 PyInstaller 冻结环境中被 .NET Framework 宿主初始化，启动器记录 `Failed to resolve Python.Runtime.Loader.Initialize` 后退出。桌面窗口栈现在固定为 `pythonnet 3.0.5` + `clr-loader 0.2.7.post0`，可在冻结 EXE 中正确初始化。任何更早 v2.1.x 构建的 Windows 用户都应换用 v2.1.4 ZIP。
- **Windows 本地构建在 EXE 启动时崩溃**，报 `ModuleNotFoundError: No module named 'backports'`：构建环境为 setuptools 80.x 时，PyInstaller 会打包 setuptools 内嵌的 `jaraco.context`，其在 Python < 3.12 下的 `from backports import tarfile` 在冻结依赖图中缺失，导致 `pkg_resources` 运行时钩子在应用启动前崩溃。Windows 构建环境现在固定 `setuptools 65.5.0` —— 与 CI 的 setup-python 提供的版本一致，其 `pkg_resources` 自包含。
- **发布冒烟测试现在覆盖打包后的 GUI 栈。** 此前它以 `PAPERREADER_NO_WINDOW=1` 启动打包后的后端，完全跳过 `webview`；v2.1.1 的窗口问题正是因此带着绿灯发布。现在打包 EXE 会额外以 `PAPERREADER_GUI_CHECK=1` 运行一次，在不打开窗口的情况下初始化 `webview.guilib`（pythonnet/.NET + WebView2 绑定），非零退出将使发布失败。
- **可移植打包更健壮。** `desktop/build_portable.ps1` 在重建前会先结束仍在运行的可移植版应用（运行中的 `PaperReader.exe` 会锁定 `dist\PaperReader`），并对 ZIP 创建重试，修复 `Compress-Archive` 因新写入文件被杀毒软件或 shell 短暂占用导致的 `base_library.zip 正由另一进程使用` 等失败。
- **中文区域设置的 Windows 上，可移植 ZIP 内不再出现乱码。** `build_portable.ps1` 与 `create_shortcut.ps1` 改为带 BOM 的 UTF-8 保存，Windows PowerShell 5.1 能正确读取其中的中文文本：ZIP 内 `使用说明.txt` 名称正常，桌面快捷方式描述正常。
- **PaperReader 内译文的中文可见。** XeLaTeX 正确嵌入了译文 CJK 字形，但 PDF.js 查看器未附带也未加载其打包的 Adobe CMaps，导致 TeX Live 的 Fandol 等 CID 字体渲染为空白。前端现在打包 PDF.js CMaps 与标准字体数据，并把 URL 提供给阅读器与产物预览两个渲染器。新翻译的文档还会优先使用 Windows 的宋体（SimSun），再回退到 macOS、Linux 与 TeX Live 字体。
- **Windows 上 LaTeX 编译不再闪现终端窗口。** 打包应用以 `CREATE_NO_WINDOW` 启动 `latexmk`；同样的保护覆盖可选的 MinerU `curl` 回退。

## 兼容性

这是向后兼容的补丁版本，无需数据迁移。目标平台仍为带 WebView2 运行时（多数现有系统已内置）的 Windows 10/11 x64；译文 PDF 生成仍只需 TeX Live（`latexmk` 与 `xelatex`）。macOS 需要 Apple Silicon 与 macOS 13+。

## 验证

使用固定窗口栈构建的打包 EXE 在 Windows 11 上启动：后端在 `127.0.0.1:8000` 健康检查通过，原生 WebView2 窗口打开。归档冒烟测试（`scripts/smoke_release.py --archive`）将 `/health` 版本与 `frontend/package.json` 比对，并以 `PAPERREADER_GUI_CHECK=1` 运行打包 EXE 一次，因此 .NET 桥或 WebView2 绑定初始化失败的冻结构建无法通过 CI。回归覆盖还检查 Windows `latexmk` 创建标志与跨平台 CJK 导言区回退；前端构建验证查看器配置与拷贝的 PDF.js 资源能一起编译。
