# PaperReader v2.1.3

> 📖 **下载前请先阅读[用户说明书](../../user_instruction.md)**，了解安装、首次配置与日常使用。本页为中文发布说明，英文原文见 [v2.1.3.md](../../releases/v2.1.3.md)。

PaperReader v2.1.3 修复了声明非 XeLaTeX 编译器的源码工程的译文 PDF 编译问题。

本版本重建过一次，追加了针对 arXiv 源码在 `\documentclass` 之前出现 `\DeclareUnicodeCharacter` 的 XeLaTeX 兼容性修复。既有 v2.1.3 下载已由下列重建产物替换。

## 修复内容

- 声明的编译器（`00README.json` → `process.compiler` 或 `% !TeX program = ...`）现在只作用于**原文**文档，与 v2.1.2 的意图一致。
- **译文**文档始终用 XeLaTeX 编译。中文支持（`xeCJK` 或 `ctex`）注入每个译文导言区，且只能在 XeLaTeX 下编译，因此声明 `pdflatex` 的工程不会再把译文构建推进无法处理中文的引擎。该修复同时覆盖自动流水线与手动重新编译端点。
- arXiv 导言区中 pdfLaTeX 专用的 `\DeclareUnicodeCharacter` 指令，在译文文档的 XeLaTeX 引擎下被中性化。兼容性定义插入到源文件第一条指令之前，原文导言区保持不变。
- 每次编译前清除过期的 `latexmk` 数据库（`.fdb_latexmk`）。此前 strict 编译失败后，`-f` 重试可能零规则执行并报告 `Nothing to do ... gave an error in previous invocation of latexmk`，而不是真正重新编译。
- 编译失败信息现在同时报告 strict 编译的原始错误与重试输出，不再被无意义的重试摘要掩盖。
- 原文编译行为与 v2.1.2 一致：遵循受支持的声明，其余默认 XeLaTeX。

## 兼容性

这是向后兼容的补丁版本，无需数据库或数据迁移。译文 PDF 生成仍需 TeX Live、`latexmk` 与 XeLaTeX；声明的引擎（如 `pdflatex`）只在编译原文时额外使用。

回归问题使用 arXiv 源码包 `2605.18309` 复现：其 `00README.json` 声明 `pdflatex`，主 TeX 文件在 `\documentclass` 之前以 `\DeclareUnicodeCharacter` 开头。原文仍用 pdfLaTeX 编译。译文文档在 PaperReader 补上缺失的原生 Unicode 兼容性定义后，用 XeLaTeX 严格编译通过；不再依赖一次恰好留下 PDF 的非零退出 `latexmk -f` 运行。

## 验证

后端测试套件新增回归：显式的译文编译器覆盖 arXiv `pdflatex` 声明、覆盖 `% !TeX program` 魔法注释、仅当源码使用 `\DeclareUnicodeCharacter` 时插入 XeLaTeX 兼容性定义、strict 编译前清除过期的 `.fdb_latexmk`、`-f` 重试前清除 strict 的错误状态，以及失败信息同时包含 strict 与宽松两种错误输出。既有编译器选择与失败 PDF 安全测试不变。`2605.18309` 完整译文源码也在本地以 strict 模式用 XeLaTeX 编译通过，含 BibTeX 与全部工程插图。
