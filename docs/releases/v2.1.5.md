# PaperReader v2.1.5

> 📖 **Read the [User Guide (中文)](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/user_instruction.md) before downloading** — installation, first-run setup, and usage. [中文发布说明](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/zh-cn/releases/v2.1.5.md)

PaperReader v2.1.5 fixes two regressions that could abort a structured (MinerU) PDF translation right after the alignment step, and turns LaTeX failures into precise, actionable diagnostics with a proper in-app TeX editor.

## What's fixed

- **Structured translation no longer crashes with `'NoneType' object is not iterable`.** The IR rendering path computed OCR math-fault repair notes but fell through without returning them, so the pipeline's loop over the notes aborted the whole document immediately after "Saved N exact bilingual alignment segments" — after the LLM translation had already been paid for. `create_translated_tex_from_ir` now returns the repair list like its markdown counterpart, and a regression test pins the contract.
- **No more `Package newunicodechar Error: Invalid argument` on translated PDFs.** The Unicode sanitizer rewrote every mapped character in the file — including the preamble's `\newunicodechar{□}{...}` declarations, whose first argument must stay a single literal character. Substituting it (e.g. to `$\square$`) broke the compile. `sanitize_and_repair` now splits complete documents at `\begin{document}` / `\end{document}` and rewrites only the body, so the same guard also protects the manual-recompile endpoint, which sanitizes the user's full document.
- **End-to-end verified on a Chinese mathematics lecture.** `testexamples/Lec1-数列极限.pdf` (Calculus I, lecture 1: limits of real sequences) now completes the full pipeline — MinerU VLM extraction, 316 structured blocks, 682 bilingual alignment segments, OCR `\sqrt` repairs, XeLaTeX compile — producing a 22-page translated PDF with zero `Missing character` warnings.

## What's new

- **Actionable LaTeX compile diagnostics.** Fatal errors are parsed from the TeX log with source line numbers (`L123: ...`), and missing glyphs are aggregated with suggested replacements (`□ (U+25A1) x4 -> replace with $\square$`). Failed compiles now report the offending lines instead of a raw `latexmk` tail, and successful compiles warn when characters render as blank.
- **OCR math-fault repair with audit trail.** MinerU occasionally reads `\sqrt[k]{a_n}` as `\sqrt[{k}/{a_n}]` (radicand swallowed into the root index) or with an unclosed index; both variants are repaired automatically and each repair is logged with its line number so the fix can be checked in the TeX editor.
- **In-app TeX editor (CodeMirror 6).** The translated `translated.tex` can be edited with syntax highlighting, search & replace (Ctrl+F / Ctrl+H), and line jumps from compile-error panels; the file can also be revealed in the system file manager or opened in VS Code. A successful manual recompile recovers a document whose pipeline run had failed.
- **Proof-mark safety net for CJK documents.** Characters common in Chinese lecture notes (□ ■ ● ○ ★ ✓ ✗, CJK-routed symbol blocks) are mapped to `amssymb` commands or the CJK font, so translated documents compile without blank glyphs.

## Compatibility

This is a backward-compatible patch release and requires no data migration. Keep the existing `DATA_DIR`, `SQLITE_DB_NAME`, `AUTH_SECRET_KEY`, account database, and user settings. Platform requirements are unchanged (Windows 10/11 x64 with WebView2, macOS 13+ on Apple Silicon; TeX Live with `latexmk` and `xelatex` for translated PDF generation).
