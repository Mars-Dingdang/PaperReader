# PaperReader v2.1.6

PaperReader v2.1.6 turns PDF translation and LaTeX compilation into a recoverable, fail-closed workflow.

## Recoverable pipeline

- A failed document can be queued again with `POST /api/document/{id}/retry`; ownership, failed-state and duplicate-request checks are enforced atomically.
- Structured extraction and verified translation chunks are checkpointed atomically. Provider key, base URL or model changes do not invalidate already verified text; source or translation-contract changes do.
- Translation failures resume from missing chunks. LaTeX failures reuse the registered `translated.tex` without repeating MinerU or translation.
- Interrupted `processing` and `recovering` records become retryable failures on the next application start.

## Safer translation and TeX

- XML/HTML-like tags such as `<think>` are protected as inert placeholders; tag-only segments bypass the model and remain in the paper.
- Placeholder order, control characters, code fences, refusals/meta-commentary, abnormal expansion and unexpected document structure are validated per segment. An invalid batch member alone is retried.
- Escaped currency dollars no longer form accidental cross-prose math regions, so text such as `Big & Tall` reaches the one-pass text escaper and renders as `Big \& Tall`.
- Real C0 bytes are removed, `⋆` is rendered as `$\star$`, and preflight reports global braces, environments, math delimiters, prose `&`, unsafe controls and unresolved glyphs while preserving legal tables and matrices.

## Bounded LaTeX recovery

- The configured OpenAI-compatible model first returns and persists a strict-JSON diagnosis; a separate call proposes exact line-range patches.
- Patches are restricted to compiler-located windows and the document body. Non-JSON, overlapping or stale patches, whole-document rewrites, package loads, file access and shell-capable commands fail closed.
- Every applied round keeps a `translated.before-repair-N.tex` backup and an audit record. Preflight and XeLaTeX run again after each patch, with a hard two-round limit.
- The progress panel shows the failed stage/chunk, diagnosis and repair history, and disables duplicate retry clicks.
