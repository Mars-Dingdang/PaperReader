# PaperReader v2.1.2

> 📖 **Read the [User Guide (中文)](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/user_instruction.md) before downloading** — installation, first-run setup, and usage. [中文发布说明](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/zh-cn/releases/v2.1.2.md)

PaperReader v2.1.2 fixes LaTeX compilation compatibility for source projects that declare a specific TeX engine instead of XeLaTeX.

## What’s fixed

- LaTeX project builds no longer unconditionally force XeLaTeX.
- arXiv source archives can declare their compiler through `00README.json` → `process.compiler`; PaperReader now respects supported declarations.
- TeX sources can also declare a compiler with the conventional `% !TeX program = ...` magic comment.
- TeX magic-comment inspection reads only the small source header instead of loading the entire `.tex` file, avoiding unnecessary I/O and memory use on large sources.
- Supported compiler declarations are `pdflatex`, `xelatex`, `lualatex`, and `latex`, mapped to the corresponding `latexmk` engine modes.
- Projects without a supported compiler declaration keep the existing behavior and compile with XeLaTeX by default.
- Compiler metadata is handled through an explicit allowlist rather than being inserted into the command line directly.
- The existing strict compilation followed by the `latexmk -f` fallback is unchanged.

## Compatibility

This is a backward-compatible patch release and requires no database or data migration. Existing projects that do not declare a compiler continue to use XeLaTeX exactly as in v2.1.1. TeX Live, `latexmk`, and the selected TeX engine must be installed on the host system.

The regression was reproduced with the arXiv source package for `2605.18309`: its `00README.json` declares `pdflatex`, while v2.1.1 forced XeLaTeX and failed at `\DeclareUnicodeCharacter`. With the v2.1.2 selector, the project is dispatched through `latexmk -pdf` as declared.

## Verification

The release gate runs the backend test suite and Python compile checks on Linux, macOS, and Windows, then builds and smoke-tests the Windows portable package and macOS application. Regression tests cover arXiv `00README.json` compiler selection, TeX magic-comment selection, the XeLaTeX default when no declaration exists, safe fallback for unsupported declarations, and consistency between API, `package.json`, and package-lock version metadata.
