# PaperReader v2.1.3

> 📖 **Read the [User Guide (中文)](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/user_instruction.md) before downloading** — installation, first-run setup, and usage. [中文发布说明](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/zh-cn/releases/v2.1.3.md)

PaperReader v2.1.3 fixes translated-PDF compilation for source projects that declare a non-XeLaTeX compiler.

This release has been rebuilt with an additional XeLaTeX compatibility fix for arXiv sources that place `\DeclareUnicodeCharacter` before `\documentclass`. Existing v2.1.3 downloads are replaced by the rebuilt artifacts listed below.

## What's fixed

- Declared compilers (`00README.json` → `process.compiler` or `% !TeX program = ...`) now apply to the **original** source document only, as intended in v2.1.2.
- **Translated** documents always compile with XeLaTeX. Chinese support (`xeCJK` or `ctex`) is injected into every translated preamble and only compiles under XeLaTeX, so a project declaring `pdflatex` can no longer push the translated build into an engine that cannot handle it. This covers both the automatic pipeline and the manual recompile endpoint.
- pdfLaTeX-only `\DeclareUnicodeCharacter` directives in an arXiv preamble are made harmless under the translated document's XeLaTeX engine. The compatibility definition is inserted before the source's first directive, while the original preamble is preserved.
- Stale `latexmk` databases (`.fdb_latexmk`) are cleared before each compile pass. Previously, after a failed strict pass, the `-f` retry could run zero rules and report `Nothing to do ... gave an error in previous invocation of latexmk` instead of actually recompiling.
- Compile failure messages now report the original strict-pass error alongside the retry output, instead of masking it with the unhelpful retry summary.
- Original-source compilation is unchanged from v2.1.2: supported declarations are honored, everything else defaults to XeLaTeX.

## Compatibility

This is a backward-compatible patch release and requires no database or data migration. TeX Live, `latexmk`, and XeLaTeX remain required for translated PDF generation; a declared engine (e.g. `pdflatex`) is additionally used only when compiling the original source.

The regressions were reproduced with the arXiv source package for `2605.18309`, whose `00README.json` declares `pdflatex` and whose main TeX file begins with `\DeclareUnicodeCharacter` before `\documentclass`. The original still compiles with pdfLaTeX. The translated document compiles strictly with XeLaTeX after PaperReader supplies the missing native-Unicode compatibility definition; it no longer relies on a nonzero `latexmk -f` run that happened to leave behind a PDF.

## Verification

The backend test suite gains regressions for: an explicit translated-document compiler overriding an arXiv `pdflatex` declaration, overriding a `% !TeX program` magic comment, adding the XeLaTeX compatibility definition only when a source uses `\DeclareUnicodeCharacter`, clearing a stale `.fdb_latexmk` before the strict pass, clearing the strict pass's error state before the `-f` retry, and failure messages containing both strict and lenient error output. Existing compiler-selection and failed-PDF-safety tests are unchanged. The complete `2605.18309` translated source was also compiled locally in strict mode with XeLaTeX, including BibTeX and all project figures.
