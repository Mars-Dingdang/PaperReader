# PaperReader v2.1

> 📖 **Read the [User Guide (中文)](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/user_instruction.md) before downloading** — installation, first-run setup, and usage. [中文发布说明](https://github.com/Mars-Dingdang/PaperReader/blob/main/docs/zh-cn/releases/v2.1.md)

PaperReader v2.1 adds secure in-app provider setup, account-scoped MinerU configuration, a native macOS application, and a focused reader UI refresh.

## What’s new

- First-run setup opens before login in the desktop app and collects the LLM endpoint, model, API key, PDF parser, MinerU options, and vision model.
- A random machine encryption key and non-secret bootstrap state are stored in the platform’s hidden local config file. Provider secrets are claimed by the first signed-in account, encrypted in SQLite, and removed from that file.
- The personal center now has Account, AI Services, and Reading tabs. Saved keys are never returned to the browser; the UI only receives configured/not-configured flags.
- LLM, MinerU, parser, and vision settings are isolated per account. Background translation jobs use the document owner’s settings snapshot.
- Windows now uses a native WebView2 window instead of Edge app mode. Existing portable `config.env` and `data` are copied into the new per-user location without deleting the originals.
- New Apple Silicon macOS 13+ app bundle uses WKWebView, is ad-hoc signed, and is distributed as a checksum-verified DMG.
- Login submission works with Enter, API errors are human-readable, backend outages have a retry state, empty states and responsive layouts are improved, and the previous preference-save loop is removed.
- Frontend bundles are split so PDF and Markdown engines load separately from the initial setup/login UI.

## Download and run

### macOS (Apple Silicon)

Download `PaperReader-v2.1.0-macOS-arm64.dmg` and its `.sha256` file. Open the DMG and copy PaperReader to Applications. The app is ad-hoc signed but not Apple-notarized, so the first launch may require Control-click → Open in Finder. TeX Live is still required to generate translated PDFs.

### Windows

Download `PaperReader-v2.1.0-Windows-x64.zip`, verify the checksum, extract the complete archive, and run `PaperReader.exe`. Windows 10/11 and the WebView2 runtime are required; current Windows installations normally include it.

On both systems the first-run wizard asks for the user’s own provider credentials. No Python or Node.js installation is required for release builds.

## Upgrade notes

- Windows v2.0 portable data/configuration is imported on first launch and left untouched as a recovery copy.
- Source installations continue to use `.env` defaults. Existing account LLM settings take precedence; legacy global provider credentials are migrated into the first signed-in account.
- New per-user database columns are added automatically. Keep the existing `AUTH_SECRET_KEY` when manually moving an authenticated source installation.

## Verification

- 40 backend tests cover migrations, encrypted secret masking, first-run claiming, account isolation, ownership, translation behavior, and parsing.
- The frontend is type-checked and built with Vite.
- The macOS arm64 app was ad-hoc signature-verified, its embedded server/UI passed the full packaged restart smoke test, and the DMG checksum was verified.
- Tagged release CI repeats backend tests on Linux, macOS, and Windows, then builds and smoke-tests both Windows x64 and macOS arm64 artifacts before publishing.
