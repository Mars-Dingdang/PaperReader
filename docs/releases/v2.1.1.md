# PaperReader v2.1.1

PaperReader v2.1.1 improves PDF reading on macOS, adds safe whole-project LaTeX archive imports, and makes visual checking opt-in for new accounts and documents.

## What’s new

- New accounts, documents, and TeX builds start with visual checking disabled. Existing saved account preferences are not migrated or overwritten; users can still enable automatic or manual checking from the sidebar or personal center.
- PDF text can be selected and copied in the macOS desktop app. Existing selection-based bilingual navigation and highlighting remain available.
- HTTP(S) links embedded in PDFs open in the system default browser, while the PaperReader window keeps the current paper and reading position. Internal PDF destinations still navigate inside the reader.
- Trackpad pinch zoom is approximately four times more responsive, with the existing 40%–300% range, cursor-centered zoom, and exact percentage entry preserved.
- The reader uses native PDF bookmarks when available. If a text-based PDF has none, it builds a hierarchical outline from section numbering, font size, and common headings such as Abstract, Introduction, References, and Appendix. Image-only PDFs show an explicit empty state.
- Complete LaTeX projects can be imported from `.zip`, `.tar`, `.tar.gz`, or `.tgz`. The app ranks likely main files using `\documentclass`, conventional names, and path depth, then waits for the user to confirm the main `.tex` before parsing or translation.
- The welcome page, sidebar, and project importer recommend LaTeX when arXiv or the publisher provides source, because it generally preserves structure and improves translation quality.

## Archive safety and limits

Archive format is checked from content before local extraction. Import accepts regular files only and rejects absolute or parent-traversal paths, links, device entries, encrypted ZIP members, duplicate/path-conflicting entries, corrupt archives, and archives without a `.tex` file. Limits are 20 MB per file, 200 MB per project including existing files, and 2,000 archive members. Extraction is staged and rolled back if validation or import fails.

`POST /api/upload` remains limited to one `.pdf` or `.tex`. Archive clients should create a project and send the package to `POST /api/project/{project_id}/archive`; its response remains the existing `ProjectDetail` shape, with `main_candidates` ordered by confidence.

## Compatibility and upgrade

- Frontend, API, desktop bundle, and release version: `2.1.1`.
- Release tag: `v2.1.1` (full SemVer; the older `v2.1` tag is not reused).
- Existing papers, accounts, favorites, and explicit visual-check preferences need no migration.
- Source installs should keep their existing `AUTH_SECRET_KEY` and `DATA_DIR`; additive database setup runs automatically.

## Download and run

### macOS (Apple Silicon)

Download `PaperReader-v2.1.1-macOS-arm64.dmg` and its `.sha256`, verify the digest, open the DMG, and copy PaperReader to Applications. The app remains ad-hoc signed and is not Apple-notarized, so first launch may require Control-click → Open in Finder. TeX Live is required to generate translated PDFs.

### Windows

Download `PaperReader-v2.1.1-Windows-x64.zip` and its `.sha256`, verify the digest, extract the complete archive, and run `PaperReader.exe`. Windows 10/11 and WebView2 are required. TeX Live remains an external requirement for translated PDFs.

## Verification

The release gate runs the full backend test suite and Python compile check across Linux, macOS, and Windows, plus a TypeScript/Vite production build. Tagged CI builds and smoke-tests the Windows ZIP and macOS application/DMG before publishing both installers and SHA-256 files.

Manual macOS acceptance covers generated and native outlines, image-only empty state, trackpad zoom, text selection/copy and bilingual navigation, plus system-browser handling of embedded HTTP(S) links.
